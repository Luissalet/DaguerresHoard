# Incorporated image engines

Daguerre contains two complete detached Rust engines and desktop editors under `native/layers` and `native/develop`. They share the normal photo-library workflows, HTTP API and MCP boundary. The product executes only `native/bin/daguerre-layers-cli` and `daguerre-develop-cli`, or their Windows `.exe` variants. Desktop editors are `daguerre-layers` and `daguerre-develop` in the same directory. An external checkout, CLI, portable bundle or future origin compatibility is not required.

Historical sources are fixed in each `PROVENANCE.json`: layered editing at `ad863217386440ca968fccc9bfff65ba24e61142`, development at `fc3fa1a71b67b3bb2aeccbf0b164bd9543288b9f`. Original MIT/Apache notices and asset attribution are retained. Fonts and the spelling dictionary retain their individual licenses; application artwork is Daguerre's existing icon.

Build all engines and editors with `python scripts/build_engines.py`; use `--debug` for the development profile. Cargo/Rust 1.95 is the tested build toolchain. Binaries and build outputs are untracked local artifacts; the script writes SHA256 receipts under `native/bin`. `--engine layers` or `--engine develop` builds one engine/editor pair.

The preferred engine keys are `layers` and `develop`. Historical `photocraft` and `lightcraft` remain aliases. Configured external paths and `DAGUERRE_*_CLI`/`DAGUERRE_CRAFT_BUNDLES` values remain user data but do not select executables. Status reports the owned paths. The complete inner tool schemas are discoverable through `image_tools`; `image_call` invokes those operations in one session. The photo lightbox creates editable copies, develops copies and opens the full incorporated desktop editor after the result appears.

The tested headless catalogs expose 18 Layers tools and 243 Develop tools. The live Develop editor exposes 379 tools, including its screen and UI operations. A GUI that remains open across a host restart is reconnected using its persisted native control port, so subsequent image operations reach the same editor. These counts describe the tested builds, rather than a fixed catalog limit.

New layered bundles use `.dglayers` and identify Daguerre as their generator. Historical `.pcraft`, PSD/PSB and raster inputs remain importable. Existing originals are not rewritten. Historical development libraries and layered-editor preferences are copied once into owned locations, leaving their originals intact; the new catalog and preset formats have their own identity and retain historical readers. Exported flat images are derivatives, while editable projects and development recipes retain their own persisted data. A new image workflow is never a replacement for the original photograph.

All 22 previous public tools remain available. Eight preferred tools add `image_engines`, `image_tools`, `image_call`, `image_create_layered_document`, `image_create_layered_photo`, `image_develop_photo`, `image_import_compositor` and `image_open_editor`: 30 total. Preferred HTTP routes use `/api/image-engine/` and `/api/agent/image_*`; historical `/api/craft/` and `/api/agent/craft_*` remain aliases. Library indexing, XMP sidecars, metadata, albums, search and original-file rules remain intact.

The imported source includes the full engine and editor; that is distinct from claiming every possible command, RAW variant, export combination or screen has been tested. The focused real tests use private synthetic data. Enable them with `DAGUERRE_NATIVE_TESTS=1` after building, then run `pytest -m craft_integration`. Default tests do not load a CLIP model. No text model is part of these engines.
